# Analysis scripts

Cross-code scripts that read every engine's per-event output and produce the
comparison figures and summary tables.

| Script | What it does | Output |
|---|---|---|
| `benchmark_analysis.py` | reads all 6 codes' outputs, builds the comparison figures + summary CSV | `../figures/`, `benchmark_summary.csv` |
| `run_benchmark.sh` | calls `benchmark_analysis.py` with the reference Geant4 run (given on the command line), PHITS's summary and the four UCMuon engines | `../figures/v2_six_code/` |
| `analyze_output.py` | single-code depth-stats helper (transmission, energy loss, angles) | `muon_depth_stats.csv` |
| `presentation_figures.py` | slide-ready figures | `../figures/` |
| `validate_backward.py` | Engine 5 (backward CSDA flux integrator) against UCMuon-MC, MUSIC and PROPOSAL: transmission T(X, θ) per zenith angle and slant opacity, all three modes; options in its header | `backward_validation.csv` in its work directory |
| `build_backward_calibration.py` | turns a calibration run of `validate_backward.py` into Engine 5's mode-2 table, in `gui/ucmuon_backward_mc.py` and `../results/backward_calibration_20261020.csv` | both |
| `bmc_density_bias.py` | the Vesuvius example's density bias from Engine 5, with and without the calibration | printed |
| `mcs_distributions.py` | multiple-scattering core widths (as E_s), tails and angular and lateral distributions of every engine, per beam and depth of the monoenergetic suite | `../results/mcs_widths_20261022.csv`, `../results/mcs_histograms_20261022.csv` |
| `geant4_survival_by_beam.py` | Geant4 survival per beam and depth of the monoenergetic suite, for the paper's survival table | `../results/geant4_survival_by_beam.csv` |
| `run_tev_bench.py` | TeV beams (1, 3, 10 TeV) through 1-3 km w.e.: UCMuon-MC, MUSIC and PROPOSAL | `../results/tev_beams_20261023.csv` |
| `mcs_thick_target.py` | the thick-target limit of multiple scattering (14.7 MeV) from the screened Rutherford cross section with a nuclear form factor, per material | printed |
| `make_inclined_inputs.py` | the inclined-beam benchmark's inputs: the six beams tilted to 60, 80 and 85°, in the engines', Geant4's and PHITS's formats, and the PHITS decks with the planes at L cos θ | `../geant4_muon_rock_v5/inclined/` |
| `inclined_summary.py` | the inclined-beam benchmark, all six codes, the vertical runs as θ = 0 | `../results/inclined_beams_20261027.csv` |
| `range_probe_50gev.py` | the end of the 50 GeV beam's range, vertical and at 85°, in Geant4 and PHITS (`inputs` writes the PHITS probe decks, `summary` the table) | `../results/range_probe_50GeV_20261027.csv` |
| `phits_energy_loss_check.py` | whether PHITS's larger energy loss on the monoenergetic beams accounts for its deficit on the realistic source | printed |

The depth-resolved survival and exit-KE tables in the paper
(`tab:survival_matrix`, `tab:exitke`) are generated by
`manuscript/scripts/make_survival_table.py`, which reads the raw `.dat` files directly
from the scratch tree.

## Run
```bash
# From anywhere; the argument is the reference Geant4 run (600 000 muons):
bash benchmark/analysis/run_benchmark.sh \
    ~/simulations/geant4/geant4_muon_rock_v5/outputs/run_stdrock_xy1km_20261022_mono

# Realistic source: the six-code summary and figures of ../run_realistic_20260614/
python3 benchmark/analysis/analyze_sixcode.py \
    ~/simulations/geant4/geant4_muon_rock_v5/outputs/run_stdrock_20261019_realistic
```
Both Geant4 runs use Standard Rock (`../codes/geant4/README.md`) and a slab
+-1 km wide (the mono run of 2026-10-19 had the default +-25 m, as wide as its
source, and lost muons out of the sides); up to 1.4.1 the references were `run_file_20260522_210114` and `run_file_20260614_095725`,
whose rock was sodium.
It writes `../figures/v2_six_code/`, whose `benchmark_summary.csv` equals
`../results/benchmark_summary_v2.csv`.

> These scripts expect the ~6 GB of raw `*_bench_<depth>m.dat` files, which live
> only in the git-ignored scratch tree `geant4_muon_rock_v5/`. Regenerate them
> with the per-code instructions in `../codes/<engine>/README.md`.
